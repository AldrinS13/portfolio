Contractor Time Log Tracker

I replaced a manual spreadsheet that health coaches used to log patient time with a form-driven system. Each coach now gets their own live time log, and the reporting team gets one clean daily summary instead of hand-merged tabs.

ROW 1 · THE PROBLEM

A tracker that broke when people used it

Health coaches log the time they spend on each patient task. The old process was a shared spreadsheet filled in by hand. Entries were retyped, totals were merged by copy and paste, and nobody could say why two reports disagreed.

The reporting team needed a daily production summary they could trust. Coaches needed to see their own entries without waiting for anyone.

Before

  • Manual entry and manual merging
  • Duplicate and missing patient entries
  • Totals that changed depending on who built them
  • No audit trail for edits

After

  • One form per entry, with an automatic case number
  • Duplicate detection built into the calculation layer
  • Each coach has a private, auto-updating log and totals tab
  • A daily summary produced from one source

ROW 2 · HOW IT WORKS

One entry, five hops

A coach submits a Google Form. A script stamps it with a case number and an edit link. A calculation sheet cleans it. A second script pushes it into that coach's own file.

Google FormCoach logs patient, task and minutes
→
Queue scriptAssigns case number and edit link, under a lockruns every 1 min
→
Calculation sheetCleans times, flags duplicates
→
Distribution scriptPushes new rows to each coach file from a rosterruns every 15 min
→
Coach filesMy Time Log, My Totals, Task Types

The delay is one 15-minute step, not two. The queue script adds about a minute, so the worst case from submit to coach log is about 16 minutes.

ROW 4 · BUGS TRACED

The hard part was finding why numbers were wrong

Most of the work after launch was diagnosis. Each bug below was found by looking at the actual formula or cell, not by guessing.

Entries swapped between patients
Symptom
A coach saw another patient's time against the wrong name.
Cause
Two helper columns each counted entries separately and drifted apart as rows were added.
Fix
Both columns now read from the same raw-combined source, so they cannot disagree.
A column of IDs vanished from the output
Symptom
The entry number column came back blank for some rows.
Cause
QUERY guesses a column's type and drops values that do not match when a column mixes numbers and text.
Fix
Switched to FILTER, which keeps every value as it is.
Minutes turned into clock times
Symptom
A time like 25:30 became a time of day, and totals were wrong.
Cause
Sheets auto-converts text that looks like a time. The same value is read differently depending on the format.
Fix
Force the column to plain text and convert with one parsing function that handles both shapes.
Wrong case number on a busy day
Symptom
Two close submissions sometimes got the same or a missing case number.
Cause
The script looked up the last row, which can change between the trigger firing and the read.
Fix
Use the row of the submission that fired the trigger, and wrap the assignment in a script lock.
A blank row received a case number
Symptom
A case number appeared on a row with no data.
Cause
A safety sweep treated any row without a case number as unfinished. This is the leading explanation, not a confirmed one.
Status
Open. Next step is to read the script execution log for that minute.

ROW 5 · DESIGN DECISIONS

Why it is built this way

Push, not pull

Each coach's file used to pull from the main file with IMPORTRANGE, which was slow and fragile. A script now pushes new rows from a roster, so a coach's file is plain data and loads fast.

Script over formula

Case numbers and edit links come from a script with a stored counter. Formulas that reference ever-growing ranges got slower with every entry.

Batch everything

Scripts read and write in blocks, never cell by cell, to stay inside the six-minute execution limit.

Measure the promise

A separate latency log records when each entry was submitted and delivered, so "under 15 minutes" is checked against data instead of assumed.

ROW 6 · WHAT I BUILT

Scope

  • Google Forms and response mapping
  • Calculation engine: case numbers, time parsing, duplicate detection
  • Internal time log and daily production summary
  • Per-coach files with protected ranges and a copyable template
  • Queue script with locking, counter and manual-review flag
  • Distribution script with a contractor roster and 15-minute trigger
  • Delivery latency monitor
  • Minutes normalizer for messy exported data
  • Coach guide, process guide, runbooks and a task tracker
  • Rollout to two batches of coaches

ROW 7 · HOW IT WAS BUILT

Built with an AI assistant, checked by me

I designed and tested this system together with Claude, an AI assistant, while teaching myself Apps Script and sheet architecture. The assistant drafted formulas and scripts. I ran them against the live sheets and reported what they actually did.

That split mattered. Several fixes were wrong the first time, and one time-parsing fix was mathematically identical to the one before it. I caught that by checking the numbers. Business rules, rollout and every decision about what counts as a duplicate were mine.

Still open: retiring the combined raw sheet so calculated columns are written by script, and deciding the future of the second form.
