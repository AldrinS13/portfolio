IT Helpdesk Ticketing & Dashboard System

My first finished project: a complete ticketing system built in Google Sheets, running from a public intake form to a live management dashboard, with SLA tracking, automated status logic and no scripts to maintain.

Role Data, Reporting & Admin Analyst
Organization Healthcare company (anonymized)
Tools Google Sheets, Google Forms, FormMule
Status Complete · in production

The Problem

Support requests were arriving through email threads, Slack messages, and verbal hand-offs — with no central record, no accountability trail, and no way to know whether an issue was even being worked on. Leadership had no visibility into response times or which departments were most affected.

No single intake

Tickets arrived through email, Slack, and chat with no standard format.

No SLA tracking

No way to measure how fast issues were resolved — or whether they breached any target.

No reporting layer

Management had to ask someone verbally for a count of open tickets.

No access control

Anyone could accidentally overwrite the raw form data if sheets weren't locked.

The Solution

A four-layer pipeline turning a Google Form into a live operational dashboard — built with pure spreadsheet formulas, no Apps Script, no code deployment, no external databases.

"The goal was a system that any team member could understand and maintain — even if I'm not in the office."

Architecture

Every downstream formula points to RAW_Data — not Form Responses 1 directly. This isolation layer means a new form field can never break the dashboards; the mirror formula absorbs the change automatically.

What Was Built

SLA Target System

Formula Columns Built (RAW_Data R:Y)

R — Ticket Status S — Open Time T — Close Time U — Time to Close V — SLA Deadline W — SLA Status ★ X — Resolution Hrs Y — Priority Rank

Column W (SLA Status) is the most complex formula in the sheet — it branches on whether a ticket is open or closed and computes elapsed time differently for each path:

Column W — SLA Status (RAW_Data)
=IF(S2="","", IF(R2="TICKET CLOSED", IF(X2="","Pending", IF(H2="High",IF(X2<=2,"Met","BREACHED"), IF(H2="Medium",IF(X2<=4,"Met","BREACHED"), IF(H2="Low",IF(X2<=24,"Met","BREACHED"),"Met")))), IF(H2="High",IF((NOW()-S2)*24<=2,"On Track","BREACHED - Open"), IF(H2="Medium",IF((NOW()-S2)*24<=4,"On Track","BREACHED - Open"), IF(H2="Low",IF((NOW()-S2)*24<=24,"On Track","BREACHED - Open"), "On Track")))))

Management Dashboard KPI Scorecards

SLA Compliance Rate (Management Dashboard)
=IFERROR(1-(( COUNTIF('Form Responses 1'!W:W,"BREACHED") +COUNTIF('Form Responses 1'!W:W,"BREACHED - Open")) /MAX(1,COUNTA('Form Responses 1'!P2:P))),0)

The dashboard also tracks: total tickets, open tickets, high-priority open, average resolution hours per agent, close rate per agent, and an alert table of unassigned open tickets.

Bugs Traced & Fixed

Three significant issues were diagnosed and resolved during development — each requiring root-cause analysis rather than just a formula tweak.

01
SLA Status blank for all open tickets
Root cause: formula started with IF(X2="",""…) — but column X (Resolution Time) is always empty for open tickets by design. The formula short-circuited before it could evaluate anything.
✓ Fix: Restructured to branch first on TICKET OPEN vs TICKET CLOSED, computing elapsed time with (NOW()-S2)*24 for open tickets directly.
02
Priority sort order wrong — Low appearing before Medium
Root cause: QUERY's ORDER BY H ASC sorts alphabetically: H(igh) < L(ow) < M(edium). Boolean sort expressions also failed due to Named Table conflicts.
✓ Fix: Added Priority Rank helper column (High=1, Medium=2, Low=3) and switched to FILTER+SORT as a backup. Accepted manual column-click sort for IT Dashboard as the production default.
03
Case No formula would have produced wrong values
Root cause: Initial approach suggested ROW()-1 for Case No in RAW_Data — but Case No is auto-assigned by FormMule with its own numbering sequence (starting at 3, 4, 5…), not 1, 2, 3.
✓ Fix: Case No is mirrored directly from Form Responses 1 column P via the ARRAYFORMULA covering A:Q, preserving FormMule's original values exactly.

Key Design Decisions

vs
RAW_Data mirror layer instead of pointing dashboards at Form Responses 1

Google Forms appends new columns when form fields change. Pointing dashboards directly at Form Responses 1 would break every formula reference. RAW_Data absorbs that change in one place — ARRAYFORMULA in A1 — while columns R:Y stay stable forever.

vs
Pure formula dashboards instead of Apps Script

Apps Script requires scheduled triggers, manual refreshes, and someone who can read JavaScript to maintain. COUNTIFS and AVERAGEIFS recalculate automatically and any analyst can audit them without touching code.

vs
Manual sort accepted for IT Dashboard ticket queue

QUERY ORDER BY with a Named Table format produced intermittent failures that were difficult to reproduce. Since IT staff already interact with the dashboard to claim tickets, clicking a column header to re-sort is a natural action — zero formula fragility for the same outcome.
